
To make the Neo encoding in `ctoolbox` precisely accurate to the native AlphaSmart Neo format (as documented in `AlphaSync` and `neotools`), the following changes are needed.

Currently, `ctoolbox` treats Neo as a static, 1-to-1 `SingleByteMapping` table with artificial `LowArea::Graphical` vs `LowArea::Control` modes. On real hardware, however, Neo text (specifically AlphaWord files) is a **stream-encoded format** that uses formatting control bytes, escape sequences (`0xB0`), and display hint codes rather than two alternate character sets.

---

### 1. Escape Sequence Handling (`0xB0 <code> 0xB0`)

On the Neo, bytes `0x00..=0x1F` and `0xA1..=0xBF` are visual glyphs in the font ROM, but several byte values are reserved by the AlphaWord engine as structural control codes.

* **Escape Syntax:** Literal character codes in ambiguous ranges are escaped as `[0xB0, <code>, 0xB0]` (or `[0xB0, <code>]` at EOF).
* **When Decoding (`Neo -> Unicode`):**
  * When `0xB0` is encountered, read the next byte as a raw character code from the Neo character set, and consume the trailing `0xB0` (if present).
  * If a byte in `0xA1..=0xBF` is encountered *without* being escaped, it is a formatting/internal code (or unknown) and should not be decoded as a character.
* **When Encoding (`Unicode -> Neo`):**
  * Any character mapped to `0xA1..=0xBF`, `0xB0`, or the graphic glyphs for `0x09`, `0x0A`, `0x0D` (such as `↵` / `U+21B5`) must be emitted wrapped in `0xB0` escape delimiters (`[0xB0, code, 0xB0]`).

---

### 2. Line Ending and Structural Control Byte Handling

* **Newlines:**
  * **Encoding:** Both `\n` and `\r` (and `\r\n`) from the host must be emitted as **unescaped `0x0D`** (not escaped, and not `0x0A`).
  * **Decoding:** Unescaped `0x0D` represents a paragraph break (decoded to `\r` by default, or converted via `LineEndingOption`).
* **Tabs:**
  * **Encoding:** `\t` is emitted as unescaped `0x09`.
  * **Decoding:** Unescaped `0x09` is decoded as `\t`.

---

### 3. Display Hints and Soft/Hard Breaks

Neo’s display engine uses special byte codes to calculate screen wrapping and word-breaking.

#### Decoding (`Neo -> Unicode`):
Unescaped formatting bytes must be normalized or stripped:
* **`0x81`** (or **`0xA1`** in older firmware): Line-breaking space $\rightarrow$ decode as standard space `' '` (`0x20`).
* **`0x8D`** (or **`0xA3`** in older firmware): Line-breaking tab $\rightarrow$ decode as standard tab `'\t'` (`0x09`).
* **`0xAD`**: Line-breaking hyphen $\rightarrow$ decode as standard hyphen `'-'` (`0x2D`).
* **`0x8F`** (or **`0xA4`** in older firmware): Hard-break display hint (inserted in long continuous words) $\rightarrow$ **ignore/strip**.
* **`0xA7`**: Pad/fill byte $\rightarrow$ **ignore/strip**.

#### Encoding (`Unicode -> Neo`):
* Maintain running counts for soft and hard breaks:
  * **Soft breaks (target interval ~40 characters):** Track the last breakable character (`' '`, `'-'`, `'\t'`). When reaching the threshold, retroactively replace that character in the output buffer with its breakable equivalent (`0x81`, `0xAD`, or `0x8D`).
  * **Hard breaks (interval ~24 characters):** If no break opportunity occurs after 24 non-breaking characters, insert an `0x8F` hard-break hint byte.
  * Reset counters whenever an unescaped break (`0x0D` newline) occurs.

---

### 4. Character Table Corrections

* **The "NOT SIGN" (`¬` / `U+00AC`):**
  * Neo has two slots for `¬`: `0x81` and `0xAC`.
  * Encoding table lookup must **always** map `¬` to `0xAC` (since unescaped `0x81` is the line-breaking space).
* **Low Area (`0x00..0x1F`):**
  * On real Neo hardware, the character set always uses the graphical glyphs (`0x25A0` for `0x00`, `0x21B5` for `0x0D`, etc.).
  * The `LowArea::Control` mode in `ctoolbox` was based on commented-out fallback code in AlphaSync. Real Neo text files handle ASCII controls by having the stream parser distinguish unescaped `0x09`/`0x0D` from escaped glyphs `[0xB0, 0x09, 0xB0]` / `[0xB0, 0x0D, 0xB0]`.

---

### 5. File Padding (Minimum File Size)

* Real Neo text files have a minimum size (typically **256** or **512** bytes).
* When serializing a file buffer for the device, pad trailing bytes up to the minimum size using the pad byte **`0xA7`**.



# Are there any other Neo control codes other than the ones you mentioned?

Yes, according to the driver documentation in `old/AlphaSync/AlphaSync/Driver/ASAlphaWordFile.cc`, the complete list of known Neo / AlphaWord control codes and escape ranges is:

### Complete Table of Neo / AlphaWord Control Codes

| Byte Code | Meaning / Function in AlphaWord | Notes & Behavior |
| :--- | :--- | :--- |
| **`0x09`** | Tab (Structural) | Horizontal tab spacing |
| **`0x0A`** | Line Feed | Sometimes found in raw streams; typically escaped if used visually |
| **`0x0D`** | End of Paragraph / Carriage Return | Structural newline / paragraph delimiter |
| **`0x81`** | Line-breaking space | Space character where the on-screen renderer is allowed to wrap lines (newer AlphaWord versions) |
| **`0x8D`** | Line-breaking tab | Tab character where the on-screen renderer is allowed to wrap lines (newer AlphaWord versions) |
| **`0x8F`** | Continuous-run break hint | Non-displayable hint inserted periodically in long unbroken words (e.g. every 16–24 characters) to allow soft wrapping |
| **`0xA1`** | Legacy line-breaking space | Equivalent to `0x81`, used in older AlphaWord firmware versions |
| **`0xA3`** | Legacy line-breaking tab | Equivalent to `0x8D`, used in older AlphaWord firmware versions |
| **`0xA4`** | Legacy continuous-run break hint | Equivalent to `0x8F`, used in older AlphaWord firmware versions |
| **`0xA7`** | Pad / Fill byte | Non-functional padding byte (used for trailing padding to reach minimum file sizes, or inserted as fill) |
| **`0xA8`** | Unknown / Hidden control byte | Does not display on the Neo screen |
| **`0xA9`** | Unknown / Paragraph-hide control byte | Appears to hide the entire line/paragraph containing it on screen (possibly for internal metadata or comments) |
| **`0xAD`** | Line-breaking hyphen | Equivalent to standard ASCII hyphen `-` (`0x2D`), but marked as an eligible line-wrap point |
| **`0xB0`** | Escape sequence delimiter | Delimits raw character glyphs: `0xB0 <code> 0xB0` |
| **`0xA1..=0xBF`** | Reserved escape/control range | The entire range `0xA1..=0xBF` is treated as reserved by AlphaWord. Any unescaped byte in this range is either a known control code above, or an untrapped internal code (and should not be directly rendered as a character) |
