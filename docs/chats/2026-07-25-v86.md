# Systematic Debugging & Bisection Plan: Guix vs. Arch v86 Execution Flow

This document outlines a structured, step-by-step strategy to debug and fix the VM/OS configuration issues in the v86 emulator (`Guix` profile vs. known-good `Arch Linux` profile) without getting trapped in repeated test-script tweaking loops.

## User Review Required

> [!IMPORTANT]
> **Strict Anti-Loop Protocol**:
> 1. **Test Scripts are Frozen**: `tests/v86_x11_verification_test.js` and `tests/v86_arch_verification_test.js` will NOT be edited to alter assertions, loosen checks, or manipulate timeouts.
> 2. **Root Cause Focus**: All investigation and modifications will target VM parameters (`v86.hbs`), engine/BIOS builds (`vendor/v86`), init processes (`v86_posix_init`), and 9p filesystem/kernel options.

## Proposed Changes & Bisection Strategy

### Phase 1: Arch Baseline Replication & Local v86 Compatibility Matrix
Isolate whether failure stems from the **v86 WASM engine/BIOS build** or the **OS runtime/configuration**.

1. **Extract & Match `copy.sh/v86` Arch Configuration**:
   - Compare settings between `index.html?profile=archlinux` (upstream copy.sh snapshot) and `assets/views/v86.hbs`:
     - **Memory Size**: copy.sh uses `128 MB` vs local `512 MB`.
     - **VGA Memory**: `8 MB`.
     - **BIOS & VGA BIOS**: `seabios.bin` and `vgabios.bin`.
     - **State file vs Filesystem**: `arch_state-v3.bin.zst` state restoration vs 9pfs boot.
2. **Intermediate Stepping**:
   - Step A: Run local Arch profile (`/v86/arch`) using upstream `v86_all.js` to establish a known-good baseline.
   - Step B: Switch local Arch profile to use local `v86.wasm` and `starter.js` modules to verify if the local v86 engine build can successfully restore and run Arch.
   - Step C: Record any VM crashes, serial output stalls, or DOM canvas rendering discrepancies.

---

### Phase 2: Guix vs. Arch Startup Flow Bisection
Once v86 engine compatibility is confirmed, bisect the startup sequence of `Guix` step-by-step against `Arch`.

#### 1. Kernel Boot & Early Init (`v86_posix_init`)
- **Kernel Cmdline Audit**:
  - Review parameters: `rw root=host9p rootfstype=9p rootflags=trans=virtio,cache=loose modules=virtio_pci tsc=reliable vga=0x344 video=vesafb:ypan,vremap:8 console=ttyS0 console=tty0 init=/init`.
- **Serial Console Logging (`ttyS0`)**:
  - Add explicit early trace logging to `v86_posix_init` (the C/Rust init daemon inside `guix_posix_initrd.cpio.gz`).
  - Trace each mount point: `/proc`, `/sys`, `/dev`, `/tmp`, and the 9p root filesystem mount (`host9p`).

#### 2. 9p Filesystem & Asset Delivery Verification
- Inspect HTTP response logs for 9p file fetches (`/vendor/v86_images/guix/guix-rootfs-flat/` and `guix-fs.json`).
- Ensure no 404s, CORS issues, or incomplete chunk transfers stall 9pfs file reads during OS startup.

#### 3. User Space, Xorg & Framebuffer Lifecycle
- Compare graphics pipeline between Arch (restored Xorg session) and Guix (framebuffer / X11 boot):
  - Check VESA resolution settings (`vga=0x344` vs standard VGA mode).
  - Verify screen canvas updates (`screen_adapter` modes and DOM bindings).

---

### Phase 3: Targeted Remediation
Based on bisection findings:
- Adjust VM options in [v86.hbs](file:///workspaces/ctoolbox/assets/views/v86.hbs).
