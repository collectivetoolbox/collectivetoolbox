For a strictly native Rust stack with zero external engine overhead (no C++, Chromium, or V8/Deno/Boa), you can build both interfaces directly on top of lightweight Rust parsing crates. \[1\]

Because this application drives a custom local HTML UI rather than arbitrary websites, you can safely skip full CSS layout trees and heavy JS engines. \[2\]

## ---

**The Shared Engine: Lightweight HTML Parsing**

To avoid massive browser engines, use one of these pure-Rust HTML parsers to read your application's UI markup:

*
* [**tl**](https://github.com/y21/tl): A zero-copy, incredibly fast HTML parser written entirely in Rust. It is perfect for embedded environments because it minimizes allocations.
* [**scraper**](https://users.rust-lang.org/t/recommendations-for-html-parsing/24453): Built on top of html5ever. It provides intuitive CSS selector queries if you need to find interactive tags quickly. \[3, 4, 5, 6, 7\]
*

## ---

**Use Case 1: Pure Teletype (Line-by-Line) Implementation**

To print pages without videoterminal escape codes, pair your HTML parser with a text-formatting transformer.

## **Recommended Architecture**

1. Use [**html2text**](https://github.com/jugglerchris/rust-html2text), a pure Rust library that renders HTML directly into a standard String or structural text annotations.
2. Configure html2text to append a numbered link configuration. It handles table formatting and lists naturally.
3. Track an internal index map (Vec\<ActionTarget\>) linking those printed numbers to their respective HTML targets or actions. \[8\]

## **Minimal Implementation Concept**

`use std::io::{self, Write};`

`struct ActionTarget {`
    `id: usize,`
    `element_type: String, // "link", "input", "button"`
    `action_payload: String, // e.g., an internal application route or event ID`
`}`

`fn main() {`
    `// 1. Raw HTML provided by your application`
    `let html_ui = r#"`
        `<div>`
            `<h1>Settings Menu</h1>`
            `<p>Select an option below:</p>`
            `<a href="app://toggle-dark-mode">Toggle Dark Mode</a><br/>`
            `<a href="app://factory-reset">Factory Reset Device</a>`
        `</div>`
    `"#;`

    `// 2. Parse and format natively`
    `// (Using html2text configs to output text blocks)`
    `let rendered_text = html2text::from_read(html_ui.as_bytes(), 80);`

    `// 3. Sequentially print page elements (Standard stdout)`
    `println!("{}", rendered_text);`
    `println!("------------------------------------------------");`
    `println!("Actions available: [1] Toggle Dark Mode | [2] Factory Reset");`

    `// 4. Clean line-by-line input processing loop`
    `loop {`
        `print!("Enter command number > ");`
        `io::stdout().flush().unwrap();`

        `let mut input = String::new();`
        `io::stdin().read_line(&mut input).unwrap();`

        `match input.trim() {`
            `"1" => println!("Executing: Toggle Dark Mode..."),`
            `"2" => println!("Executing: Factory Reset..."),`
            `_ => println!("Unknown action number. Try again."),`
        `}`
    `}`
`}`

## ---

**Use Case 2: Videoterminal / Curses (2D TUI) Implementation**

If you want a classic 2D interactive terminal window (like *Lynx*), you will need layout capabilities that handle navigation. \[9\]

## **Recommended Architecture**

1. Use [**ratatui**](https://ratatui.rs/): The dominant pure-Rust framework for constructing terminal user interfaces. It features completely native compilation with absolute zero external C-dependencies if you use its crossterm backend. \[9\]
2. Pass your HTML string through tl or scraper to isolate structural chunks (like headers, paragraphs, and list items). \[4, 5, 10\]
3. Feed those chunks directly into Ratatui's **Paragraph** or **List widgets**. \[9\]
4. Track the coordinates or index of active interactive elements. When the user utilizes arrow keys, alter the background/foreground colors of the targeted text sequence via Ratatui's Style attributes to display a "focused cursor" look. \[9\]

**Comparison of Dependencies**

| Resource Metric | Teletype Approach (html2text \+ std::io) | Videoterminal Approach (tl \+ ratatui) |
| :---- | :---- | :---- |
| **Compiled Binary Overhead** | Minimal (\< 1 MB added) | Low (\~1.5 to 2 MB added) |
| **C Dependencies** | **None** (Pure Rust) | **None** (Pure Rust) |
| **Memory Footprint** | Extremely low (Stack allocations \+ Strings) | Low (Bounded UI frame double-buffering) |
| **Execution Paradigm** | Streaming/Blocking pipeline | Event-driven frame drawing cycle |
