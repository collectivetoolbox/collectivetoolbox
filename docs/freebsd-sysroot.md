# FreeBSD Source Sysroot Review

## Pending Work

No reviewed upstream file manifest is supplied yet. Generation intentionally
fails closed until one is provided. A compiler-usable FreeBSD sysroot and its
build-time library compilation have not been verified. The existing vendored
trees have not been audited or regenerated by this change.

The former synthetic headers have been removed. LLVM syscall definitions are
not evidence of FreeBSD syscall numbers, and ARM64 headers cannot establish the
x86-64 ABI. Missing or incompatible architecture headers must not be replaced
by guessed definitions. Any future independently authored replacements need
ABI tests and their own licensing review. Any future multi-source generator
must preserve every contributor's copyright and license management information
in each derived file; the downloader currently performs no such transformations.

The standalone compilation script still expects the old temporary source
layout. It is not invoked by the downloader and has not been adapted or audited
here. Build integration must use reviewed sources, produce object code only in
build output, and preserve the source-only vendored trees.

## Trust Boundary

Run `python3 -B scripts/download-freebsd-sysroot.py --manifest PATH` with a
trusted, independently reviewed manifest. The manifest is a review record, not
a license scanner's output. Do not generate approvals from SPDX identifiers,
filename extensions, or fragments of familiar license language. An SPDX tag
alone cannot certify all material in a file. The script's license identifier
allowlist is only a veto on approvals, not evidence that an approval is correct.

Review the complete exact upstream file and its provenance, including embedded
third-party material, all copyright statements, restrictions, exceptions,
directory-level licensing, referenced license texts, and applicable notices.
Resolve every applicable license to an AGPL-3.0-or-later-compatible set of
terms. If uncertain, do not approve the file. The reviewer must also verify that
the file is genuine source, not encoded firmware, an object represented as an
array, or another binary blob disguised as text. Text and binary-signature
checks are defense in depth, not substitutes for that review.

All required companion license and notice files must have their own reviewed
entries and be listed in the source entry's `notices`. An empty list explicitly
asserts that the reviewer found no additional required notice files. Copying
an Apache/LLVM header, for example, requires preserving the applicable complete
license/exception text and any required upstream notices, not just its SPDX tag.

## Manifest Format

The JSON object has exactly three keys:

- `version`: integer `1`.
- `commits`: the `freebsd` and `llvm` commit hashes pinned in the downloader.
- `files`: a nonempty list of reviewed entries.

Each entry has exactly these fields:

- `repository`: `freebsd` or `llvm`.
- `path`: canonical relative POSIX path in the pinned upstream Git tree.
- `destination`: canonical relative path within the generated sysroot.
- `sha256`: lowercase SHA-256 of the exact reviewed Git blob bytes.
- `kind`: `source` or `notice`.
- `licenses`: nonempty list of all applicable reviewed license identifiers.
- `review`: nonempty reference to the reviewer and recorded evidence/rationale
  for the complete file's licensing, provenance, and required notices.
- `source_only_reviewed`: boolean `true`, certifying source-only content,
  including review for embedded binary payloads; notices must be plain text.
- `notices`: list of required companion notice paths in the same repository.

Each applicable license identifier must be in the script's explicit allowlist.
All SPDX tags in the file are checked against the reviewed identifiers. Only
individual identifiers and simple `AND` expressions are supported. Other
expressions, including `OR`, parentheses, and unknown exceptions, are rejected
even if a legal review might eventually establish compatibility. This is a
deliberate false-negative preference, not a determination of incompatibility.
Files without SPDX tags still require the same complete human review and hash.

Source destinations are restricted to headers under `usr/include` and supported
source/definition files under `src`. Notices go under `share/licenses`. Objects,
archives, executables, symlinks, and executable-mode Git files are not accepted.
Currently only UTF-8 text is accepted; other encodings require a reviewed policy
change, not lossy decoding or stripping of notices.

Every selected file is copied byte-for-byte. No compiler is run, no source
comments are stripped, no files are concatenated, and no ABI definitions are
invented. The generated `reviewed-manifest.json` records all selected sources,
digests, and review references. Validation is completed in a temporary tree
before either existing sysroot is replaced. A failed download, digest check,
or source/notice check leaves both existing sysroots untouched.

## Regression Tests

Run `python3 -B -m unittest discover -s tests -p test_freebsd_sysroot.py -v`.
Tests use local repositories and temporary output trees, without upstream
downloads or modifications to vendored files. They validate the enforcement
mechanism, not the licensing or ABI correctness of an actual upstream sysroot.
