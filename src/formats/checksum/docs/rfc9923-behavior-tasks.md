# RFC 9923 Reference Implementation Analysis & Task List

This document provides a behavior-focused analysis of the reference C
implementation contained in RFC 9923 Section 8, cataloging behavioral
aspects managed by the reference code and defining a prioritized task list for
the `ctb-formats-checksum` crate.

---

## 1. Behavioral Aspects Managed by the Reference Implementation

### 1.1 Digest Endianness
- **Specified Behavior:**
  - RFC 9923 Section 2.3 ("FNV Endianism") explicitly states:
    *"For persistent storage or interoperability between different hardware
    platforms, an FNV hash shall be represented in the little-endian format...
    the FNV hash will be stored in an array hash[N] with N bytes such that its
    integer value can be retrieved as: `for ( i = N-1, value = 0; i >= 0; --i )
    value = ( value << 8 ) + hash[i];`"*
  - The RFC also states that its byte-vector functions return little-endian
    vectors for every supported width.
- **Impact & Pitfall:**
  Display hex formatting (e.g. Tables 1 and 2) is big-endian, while portable
  binary serialization is little-endian. These are distinct representations.

### 1.2 Dual Interface Paradigms (Native Integer vs Byte Vector)
- **Reference Behavior:**
  - Distinct entry points exist for raw machine words vs byte vectors:
    `FNV32INTstring`, `FNV32INTblock`, `FNV32INTfile` vs `FNV32string`,
    `FNV32block`, `FNV32file`.
  - Compile-time feature flag `FNV_64bitIntegers` configures whether 64-bit
    multiplication is natively used or broken down into 16-bit multiplications.
- **Impact & Pitfall:**
  Native integer returns are platform-endian dependent when transmitted over
  networks, whereas byte vectors are intended for portable serialization.

### 1.3 State Machine and Context Lifecycle Tracking
- **Reference Behavior:**
  - Context structures maintain a sentinel field `ctx->Computed` tracking four
    states: `FNVinited`, `FNVcomputed`, `FNVemptied`, `FNVclobber`.
  - Hashing into an uninitialized context or finalized context returns
    `fnvStateError`.
  - Finalizing (`FNVxxxresult`) zeroes the internal accumulator
    (`ctx->Hash[i] = 0;`) and transitions state to `FNVemptied`.
- **Impact & Pitfall:**
  Prevents accidental double-extraction or reuse of dirty context state.

### 1.4 String vs Block Semantics and Null-Byte Inclusion
- **Reference Behavior:**
  - `FNVxxxstring`: Traverses until null byte `\0`, hashing all characters
    **excluding** the trailing `\0`.
  - `FNVxxxblock`: Takes an explicit byte length.
  - In `main.c`, block test vectors (`bvalues`) are generated by passing
    `strlen(s) + 1` bytes, thereby explicitly hashing the trailing `\0`.
- **Impact & Pitfall:**
  Hashing `"foobar"` as a string yields `0xbf9cf968`, while hashing `"foobar"`
  with its trailing null byte yields `0x0c1c9eb8`.

### 1.5 Defensive Bounds and Parameter Validation
- **Reference Behavior:**
  - Explicit checks for `NULL` input pointers (`fnvNull`).
  - Explicit checks for negative buffer lengths (`fnvBadParam`).
  - File reading in fixed 1024-byte buffer chunks with `ferror` checks.

## 2. Behavior-Focused Task List for `ctb-formats-checksum`

### Phase 1: Serialization Consistency & Interoperability (High Priority)
- [x] **Correct Modulo Bias Avoidance Formula**:
  Ensure `fnv1a_range_u64` and `fnv1a_range_u32` use $2^S - 1$ ($S=64$ and
  $S=32$) rather than $2^{128} - 1$ per RFC 9923 Section 3.
- [x] **Custom Basis Support for Multi-Value Chaining**:
  Provide `with_basis` constructors on `FnvStream` and helper functions
  `fnv1a_32_with_basis`, `fnv1a_64_with_basis`, and `fnv1a_128_with_basis`
  per RFC 9923 Section 4.
- [x] **Wire Serialization vs Display Hex Clarification**:
  Document and verify that:
  1. `to_be_bytes()` matches RFC 9923 Table 1/2 hex representations.
  2. `to_le_bytes()` matches RFC 9923 Section 2.3 little-endian wire format.
  3. Test both representations across all supported sizes.

### Optional High-Level Multi-Value APIs
These are application protocol conveniences, not missing FNV or RFC behavior.
RFC 9923 recommends preserving component boundaries but does not prescribe a
particular length encoding or delimiter.

- [ ] **Length-Prefixed Multi-Value Hasher (Optional)**:
  Implement a helper struct `FnvMultiHasher<const BYTES: usize>` that accepts
  sequences of byte slices and prepends an application-defined length encoding.
- [ ] **Delimiter Framing Helper (Optional)**:
  Implement helper for null-delimited or sentinel-delimited sequential hashing.
- [ ] **Parallel Hash Composition Utility (Optional)**:
  Implement the chunk-partitioned concurrent construction discussed, but not
  normatively specified, by RFC 9923 Section 4.

### Unrelated or Unnecessary Work
- [ ] **File Chunking Streamer (Separate CLI Concern)**:
  Implement chunked file reader for `csum` CLI to avoid buffering large files in
  memory.
- [x] **Finalize Lifecycle**:
  `FnvStream::finalize(self)` consumes the stream, so Rust prevents updates or a
  second extraction afterward. FNV state is not secret material, and zeroizing
  it is not an RFC requirement.
- [x] **Clean-Room Test Vectors**:
  Tests use constants and vectors stated in the RFC. Compiling or extracting
  the RFC's C implementation would undermine the clean-room boundary and is not
  required for conformance testing.
