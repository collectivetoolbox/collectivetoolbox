- Guix Mesa 25.2.3 cross builds for i686 can fail with `Dependency "libclc" not found` even though Mesa lists `libclc` in native-inputs.
- Root cause: Mesa's Meson checks `dependency('libclc')`, and `libclc.pc` lives in the native input's `share/pkgconfig`, which the cross pkg-config wrapper does not see by default.
- Local fix in `scripts/guix/patches/mesa.scm`: prepend the relevant build prefixes before Mesa's configure phase so cross Meson/CMake discovery can see existing Guix metadata: `libclc` via `PKG_CONFIG_PATH`, `llvm-for-mesa` via `CMAKE_PREFIX_PATH` and `PATH`, plus `spirv-tools` and `spirv-llvm-translator` pkg-config/CMake metadata. Also provides shell-based llvm-config wrapper for llvmpipe Gallium rasterizer support on i686.
- `guix build: error: corrupt input while restoring archive`:
  - Cause: Guile auto-compilation banners (`note: source file ... newer than compiled ...`) emitted into stdout when Guix helper tools (`guix substitute`, `perform-download`) communicate with `guix-daemon` over standard I/O IPC. Fixed by exporting `GUILE_AUTO_COMPILE=0` and `GUILE_WARN_DEPRECATED=no`.
