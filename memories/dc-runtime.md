- Dc document display IS execution, like PostScript (operator clarification 2026-10-02). Runtime executes; renderer lowers/projects its semantic snapshot. See docs/renderer-flow.md.
- Only bounded pure compute is available without authorization. Local-node reads, persistent storage, file/network I/O, large memory, high CPU and high-resolution timers require user-authorized capabilities.
- Unknown/malformed constructs do not require a strict-validation pass before attempting execution; preserve permissive recovery/continuation and capability gating.
- Never generalize non-evaluating parsing/raw inspection or non-executing quoted payloads into a ban on execution during normal display. If indexing evaluates, it uses the capability-gated runtime, not ambient indexer privileges.
- Removed misleading 'display without executing' and strict-validation-before-execution wording from docs/mvp-roadmap.md and docs/file-info.md on 2026-10-02; older file-info wording dated to afd3507f52 (2026-09-17).

- File metadata snapshot container is Dc 321..322. Do not introduce a second native-metadata snapshot tag. Native observations use a generic keyed map (313..314) directly within that record; raw flags with source OS and unknown-bit provenance use Dc 539, distinct from semantic flags 388..389. Dc 540 now references a lexically bound value in .EL Syntax (2026-10-08); its name is a Dc 270..271 identifier, not an executable string. Dc 269 remains infix assignment. Dc 541/542 enter/exit reference scopes; inner declarations shadow outer ones and document-local bindings expire on scope/document exit.

Their ad-hoc codecs from 2d300b56e were replaced with DcMixed key_value records (explicit dc(key) fields) and names enums (explicit dc(name) variants). Dc 313 requires two type headers and Dc 312 separators; BTreeMap and keyed derives now emit/check these. Dc 539 carries a keyed record. Malformed previous map bytes are rejected, not migrated. - Textual binary encapsulation metadata nesting is a caller-configurable resource budget (`DcProjectionPolicy::max_encapsulation_metadata_depth`, default 32), not a hardcoded guard; exceeding it is a hard error under every diagnostic policy (like `max_binary_metadata_bytes`). `encapsulation::Cursor::read_payload` walks nested checksum metadata with an explicit frame stack and must stay non-recursive: raising the budget must never risk stack exhaustion (2026-10-17, verified at 20k levels). Policy-free utility entry points (`DcMstring::from_dc_str`, `push_binary_with_metadata`, `to_dc_string`, `write_text`, `validate_metadata`) still enforce only the default budget.
- Dc structural/semantic role classification (`DcRole`) and `<equiv>` alias resolution are generated from the CSV database and resolved through `SyntaxRuleResolver` (`DcChar::fills_role_with(role, resolver)` / `resolver.canonical_token`). Procedural readers and derives must use role/equivalence queries rather than numeric Dc allowlists or direct `DcChar` constant comparisons, and single-token `<equiv>` aliases must not carry redundant syntax formulas that diverge from their canonical target.
- Keep lexical quoting (`DcRole::BeginLiteral` `252..253`, `DcRole::BeginIdentifier` `270..271`, `DcRole::Escape` `255`) distinct from evaluated expressions and stream-splicing calls (`spliced_tokens`). Quoting disables structural/escape role dispatch without evaluating expressions; spliced token streams (`DcRole::InvokeRoutine` `309` with `spliced_tokens` callbacks) expand at the token-stream cursor boundary before framing/grammar validation, whereas typed expression evaluators (`DcExpressionEvaluator`) yield typed values (`DcEvaluatedValue`) for value projection (`397` / `561` / `540` / `256` / `516` / `535`).
