- Dc document display IS execution, like PostScript (operator clarification 2026-10-02). Runtime executes; renderer lowers/projects its semantic snapshot. See docs/renderer-flow.md.
- Printing and returning document values are the same evaluated-document operation (operator clarification 2026-11-09). `lang.say` contributes its decoded string plus a final LF if absent; emitted closers can close surrounding blocks. Do not turn source-literal quoting into a prohibition on interpreting those tokens after emission. Value evaluation and stream emission share the same result, including LF; do not substitute the argument node and lose that LF.
- Historical `.ems` hello-world fixtures contain whitespace-separated decimal Dc shorthand: use `converters::dcal::dcsh_to_dcmstring`, not the DcText/DcTS literal text transports. Exact ASCII fixture comparison requires explicit graph-equivalence normalization (`AsciiSettings.normalization = Some(DcNormalizationMode::All)`); default strict ASCII export does not normalize historical short-character spellings.
- Only bounded pure compute is available without authorization. Local-node reads, persistent storage, file/network I/O, large memory, high CPU and high-resolution timers require user-authorized capabilities.
- Unknown/malformed constructs do not require a strict-validation pass before attempting execution; preserve permissive recovery/continuation and capability gating.
- Never generalize non-evaluating parsing/raw inspection or non-executing quoted payloads into a ban on execution during normal display. If indexing evaluates, it uses the capability-gated runtime, not ambient indexer privileges.
- Removed misleading 'display without executing' and strict-validation-before-execution wording from docs/mvp-roadmap.md and docs/file-info.md on 2026-10-02; older file-info wording dated to afd3507f52 (2026-09-17).

- Textual binary encapsulation metadata nesting is a caller-configurable resource budget (`DcProjectionPolicy::max_encapsulation_metadata_depth`, default 32), not a hardcoded guard; exceeding it is a hard error under every diagnostic policy (like `max_binary_metadata_bytes`). `encapsulation::Cursor::read_payload` walks nested checksum metadata with an explicit frame stack and must stay non-recursive: raising the budget must never risk stack exhaustion (2026-10-17, verified at 20k levels). Policy-free utility entry points (`DcMstring::from_dc_str`, `push_binary_with_metadata`, `to_dc_string`, `write_text`, `validate_metadata`) still enforce only the default budget.
- Dc structural/semantic role classification (`DcRole`) and `<equiv>` alias resolution are generated from the CSV database and resolved through `SyntaxRuleResolver` (`DcChar::fills_role_with(role, resolver)` / `resolver.canonical_token`). Procedural readers and derives must use role/equivalence queries rather than numeric Dc allowlists or direct `DcChar` constant comparisons, and single-token `<equiv>` aliases must not carry redundant syntax formulas that diverge from their canonical target.
- Keep lexical quoting (`DcRole::BeginLiteral` `252..253`, `DcRole::BeginIdentifier` `270..271`, `DcRole::Escape` `255`) distinct from evaluated expressions and stream-splicing calls (`spliced_tokens`). Quoting disables structural/escape role dispatch without evaluating expressions; spliced token streams (`DcRole::InvokeRoutine` `309` with `spliced_tokens` callbacks) expand at the token-stream cursor boundary before framing/grammar validation, whereas typed expression evaluators (`DcExpressionEvaluator`) yield typed values (`DcEvaluatedValue`) for value projection (`397` / `561` / `540` / `256` / `516` / `535`).
- Reach for `DcMstr` / `DcMstring` by default for almost all Dc string use cases (including `DcDocumentNavigator` / `DcSyntaxKind` literal, identifier, and assignment payloads): `DcMstr` and `DcStr` represent and process the exact same set of documents and arbitrary Document Characters (`DcChar`s, including short Dcs, long Dcs, and format Dcs), but `DcMstr` optimizes for space whereas `DcStr` will dramatically inflate storage requirements on any document containing encapsulated binary data. Reserve `DcStr` / `DcString` as a situational tool for tight loops over short pure-character sequences where format simplicity is prioritized.
- The minimal trusted bootstrap kernel is explicitly versioned via `BootstrapKernelVersion` (`BootstrapKernelVersion::V1 = 1` in `src/formats/dcstring/navigator/policy.rs`) and specified in `docs/bootstrap-kernel-spec.md`. `DcWasmSession` (`src/formats/dcstring/converters/wasm.rs`) enforces runtime-independent `DcWasmResourceLimits` on unmodified `tinywasm 0.8.0` via portable `.wasm` bytecode instrumentation (`src/formats/dcstring/converters/wasm_quota.rs`): deduct-before-effect compute-quota accounting (`max_instructions_per_step` / `WasmResourceInterruption::ComputeQuotaExhausted`), linear-memory page caps across instantiation / `provide_input` / `memory.grow` (`max_memory_pages` logical `-1` denial vs. `physical_max_memory_pages` `MemoryLimitExceeded` interruption), table element caps (`max_table_elements` vs. `physical_max_table_elements` `TableLimitExceeded`), single-step output byte caps (`max_step_output_bytes`), cumulative session output byte caps (`max_session_output_bytes`), and task-level quota sharing (`SharedWasmTaskQuota`). VM resource interruptions (`WasmResourceInterruption`) map to `Privilege::ExcessiveCompute`, are recorded as `WasmTraceEvent::ResourceInterruption` entries in `WasmExecutionTrace` (`src/runtime/runtime.rs`), and support resumable continuation via `DcWasmSession::increase_compute_quota` when `PermissionDecision::Allow` is granted. Historical graph pinning (`Dc 641`) governs only document/language semantics; capability authorization remains strictly in the host `ExecutionContext`, and `replay_wasm_session_trace` compares logical capability requests and exact compute-quota interruption boundaries before supplying recorded responses.
